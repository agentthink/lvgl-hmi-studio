# 02 · 技能模块

## 1. 能力清单

`skills/registry.json` 是技能的**唯一权威清单**（运行时由 `SkillRegistry` 加载）：

| 技能 | 能力 | 适用场景 | 触发条件 | 必填输入 | 前置依赖 | 后置校验 |
| --- | --- | --- | --- | --- | --- | --- |
| `codegen` | 代码生成 | 从零实现新功能 / 按规格生成骨架 / 工具函数模板 | 生成、实现、编写、写一个、create、implement | 无（request/spec 二选一） | 无 | 无 |
| `debug_fix` | 调试修复 | 上报报错定位根因 / 语法与静态诊断 / 修复后回归 | 报错、错误、bug、修复、异常、traceback | `source` | 无 | **unit_test** |
| `unit_test` | 单元测试 | 验证新代码 / 回归测试 / 补充用例 | 测试、单测、验证、用例、回归、test | `source` | 无 | 无 |
| `doc_writing` | 文档编写 | README / API 文档 / 变更记录 | 文档、说明、readme、doc、写文档 | 无（source/content 二选一） | 无 | 无 |
| `perf_opt` | 性能优化 | 定位耗时卡顿 / 复杂度评估 / 反模式识别 | 性能、优化、慢、耗时、内存、perf、benchmark | `source` | 无 | **unit_test** |

> **调用关系语义**：
> - `dependencies`（前置）：执行本技能前必须已运行的其他技能（当前五个技能均无前置依赖）。
> - `post_checks`（后置）：本技能执行后**必须**衔接的校验技能——`debug_fix` 修复后、`perf_opt` 优化后都强制回归 `unit_test`，保证"修复/优化不引入回归"是硬约束而非建议。
> - `suggested_next`（建议）：非强制衔接建议（如生成代码后建议补测试和文档）。

## 2. 技能契约（SkillMeta）

每个技能通过 `SkillMeta` 声明四类契约，基类 `BaseSkill.__call__` 统一执行"输入校验 → 运行 → 结果包装"：

```python
# skills/core/skill_base.py（节选）
@dataclass
class SkillMeta:
    name: str                 # 技能唯一标识
    display_name: str         # 中文显示名
    description: str          # 能力描述
    module_path: str          # 实现模块（动态导入用）
    class_name: str           # 实现类名
    scenarios: list[str]      # 适用场景
    triggers: list[str]       # 触发条件（关键词，用于意图检测）
    inputs: dict              # 输入参数说明 {key: 说明}
    outputs: dict             # 输出字段说明 {key: 说明}
    required_inputs: list[str]  # 必填输入
    dependencies: list[str]   # 前置依赖
    post_checks: list[str]    # 后置校验
    suggested_next: list[str] # 建议衔接技能

class SkillResult:            # 统一结果：success / data / error / elapsed_ms
    ...
```

**输入校验**：`__call__` 自动检查 `required_inputs`，缺失即返回失败结果，绝不抛裸异常；
**输出契约**：`data` 为 dict，其键与 `meta.outputs` 声明一一对应，下游技能按约定消费。

## 3. 触发条件与意图检测

`SkillRegistry.match_triggers(text)` 对每个技能的触发词做子串匹配（忽略大小写），
按命中数降序返回；编排器据此识别主技能：

```
"我的 demo_add 模块报语法错误，修复后请生成单元测试、写文档、做性能优化"
   -> debug_fix(报错+修复=2) > unit_test(单元测试=1) = doc_writing(文档=1) = perf_opt(性能优化=1)
   -> 主技能 debug_fix，其余按注册表顺序衔接
```

## 4. 编排器（SkillOrchestrator）

```
执行流程：
  1. 意图检测      detect_skills(text)           -> 候选技能（按得分排序）
  2. 链路规划      plan_chain(text, explicit)    -> [主技能] + [其他命中] + [后置校验补全]，去重
  3. 顺序执行      execute(text, context)        -> 前一步输出合并进 context；失败即停（fail-fast）
```

**上下文传递约定**（关键契约）：

```python
# orchestrator.py（节选）
if result.success:
    merged.update(result.data)                  # 技能输出合并进上下文
    if result.data.get("fixed_code"):           # 特殊约定：debug_fix 的修复结果
        merged["source"] = result.data["fixed_code"]   # 回填 source，下游自动消费修复版
```

即：`debug_fix` 修复后，后续 `unit_test` / `doc_writing` / `perf_opt` 自动基于**修复后**代码工作，
无需调用方手动传递。

## 5. 各技能实现要点

| 技能 | 实现 | 输入 | 输出 |
| --- | --- | --- | --- |
| `codegen` | 关键词模板库（HTTP/排序/文件/计算器）+ 规格骨架生成 | `request` 或 `spec` | `code/language/filename/notes` |
| `debug_fix` | `ast.parse` 语法诊断 + 未定义名/未用导入启发式 + 安全自动修复（补冒号等） | `source`（必填）、`error` | `root_cause/diagnosis/fixed_code/auto_fixed/issues` |
| `unit_test` | 从 AST 抽函数签名 → 生成 unittest 用例（冒烟 + 显式断言）→ 子进程执行 → 解析统计 | `source`（必填）、`cases` | `test_code/passed/failed/output` |
| `doc_writing` | 抽取模块 docstring 与函数签名 → 渲染 README/API/changelog 模板 | `source` 或 `content`、`doc_type` | `document/doc_type/path` |
| `perf_opt` | AST 统计循环深度（复杂度标签）+ 循环内字符串拼接/append 反模式识别 | `source`（必填） | `complexity/report/suggestions` |

## 6. 新增一个技能（扩展指南）

```bash
# 1. 建目录与实现类（继承 BaseSkill，实现 run()）
mkdir skills/my_skill && touch skills/my_skill/__init__.py

# 2. 在 registry.json 注册一行（含场景/触发/输入输出/调用关系）
# 3. 在 tests/test_skills.py 补两条用例
```

约束：技能**禁止 import 第三方库**；输入输出必须与 `meta` 声明一致；
若需要"执行后必须验证"，把校验技能填入 `post_checks`。
