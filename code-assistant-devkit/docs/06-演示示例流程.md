# 06 · 演示示例流程（三模块协同）

> 本节展示技能模块、环境模块、服务模块如何协同完成一次真实任务。
> 以下输出为 2026-08-15 在本仓库**真实运行**的结果（完整报告见
> [outputs/demo-report.md](outputs/demo-report.md)，可随时 `make demo` 复现）。

## 1. 演示目标

一条完整业务链路：**用户诉求 → 技能编排（修复→测试→文档→优化）→ 静态分析 → 构建 → 部署 → 日志监控 → 回滚**。

## 2. 演示素材

- **演示项目**：`examples/demo_project/`（`demo-add` 0.1.0），模块源码刻意含两类缺陷：
  - `def add(a, b)` **缺冒号**（语法错误，供 debug_fix 自动修复）
  - `total_str` 循环内字符串拼接（O(n²) 反模式，供 perf_opt 识别）
- **用户诉求**：`我的 demo_add 模块报语法错误，修复后请生成单元测试、写文档、做性能优化，再构建部署到 staging 环境`
- **测试用例**：`add(1,2)==3`、`total_str([1,2,3])=="1,2,3"`

## 3. 第一步：技能模块（能力清单）

由 `SkillRegistry` 加载 `skills/registry.json`，5 项技能全部就绪：

| 技能 | 能力 | 必填输入 | 后置校验 |
| --- | --- | --- | --- |
| `codegen` | 代码生成 | 无 | 无 |
| `debug_fix` | 调试修复 | source | **unit_test** |
| `unit_test` | 单元测试 | source | 无 |
| `doc_writing` | 文档编写 | 无 | 无 |
| `perf_opt` | 性能优化 | source | **unit_test** |

## 4. 第二步：技能编排（意图检测 → 链路规划 → 顺序执行）

触发条件命中：`debug_fix`（"报错"+"修复"，得分最高）> `unit_test` / `doc_writing` / `perf_opt`（各命中 1 词）。

编排器自动补全**后置校验**，得到执行链并逐级执行（前一步输出自动成为下游输入，
`debug_fix` 的 `fixed_code` 回填 `source`，下游技能全部基于修复后代码工作）：

```
执行链：debug_fix → unit_test → doc_writing → perf_opt
总耗时：46.5 ms，结果：全部成功
```

| 步骤 | 技能 | 结果 | 摘要 |
| --- | --- | --- | --- |
| 1 | `debug_fix` | ✅ 0.1ms | 已自动修复（补冒号），发现 1 个问题 |
| 2 | `unit_test` | ✅ 44.1ms | 生成并执行 4 条用例（2 冒烟 + 2 断言），通过 4 / 失败 0 |
| 3 | `doc_writing` | ✅ 0.4ms | 生成 README 文档（18 行）→ `examples/demo_project/README.md` |
| 4 | `perf_opt` | ✅ 0.2ms | 分析 2 个函数，识别出 1 个性能问题 |

**debug_fix 自动修复产物**（`def add(a, b)` 缺冒号被补上）：

```python
def add(a, b):
    """两数相加。"""
    return a + b
```

**perf_opt 优化建议**：

> 第 12 行：循环内字符串拼接 `out = out + ...` 为 O(n²) 复杂度，
> 建议改为收集到 list 后一次性 `",".join(...)`

**关键机制**：因为 `unit_test` 是 `debug_fix`/`perf_opt` 的**后置校验**，
"修复/优化必须回归通过"是硬约束——若修复后测试失败，链路会在该步**立即中止**（fail-fast）。

## 5. 第三步：服务模块（分析 → 构建 → 部署 → 日志）

演示脚本在线程中启动真实 uvicorn 服务（`127.0.0.1:8123`），随后以 HTTP 调用四个接口
（携带 `X-API-Key: dev-key-001`）：

### 5.1 静态分析

```
POST /api/v1/analysis  {"file_path": "examples/demo_project/src/demo_add/__init__.py"}
→ SLOC：10，函数数：2，问题数：0（无）     # 修复后代码干净通过
```

### 5.2 构建打包

```
POST /api/v1/build  {"project_dir": "examples/demo_project"}
→ build_id：2e1e2d657428
→ 产物：.runtime/builds/demo-add-0.1.0.tar.gz（921 字节，4 个文件，语法编译错误 0）
```

### 5.3 自动部署

```
POST /api/v1/deploy  {"artifact_path": ".../demo-add-0.1.0.tar.gz", "env": "staging"}
→ deploy_id：72c81879c947，版本：0.1.0 → staging
→ 发布目录：.runtime/releases/staging/0.1.0/
```

### 5.4 日志监控

```
GET /api/v1/logs?service=deploy
→ 共 1 条（本次链路记录；演示开始时已清空历史日志）
  [INFO] 2026-08-15T13:18:20+08:00 deploy: 部署完成: 0.1.0 -> staging
```

### 5.5 回滚

```
POST /api/v1/deploy/rollback  {"env": "staging"}
→ 回滚后当前版本：0.1.0（note: 回滚至 0.1.0）
```
