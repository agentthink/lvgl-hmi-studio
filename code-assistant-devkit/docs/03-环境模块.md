# 03 · 环境模块

## 1. 依赖管理

| 文件 | 作用 |
| --- | --- |
| `pyproject.toml` | 项目元数据、运行依赖、`devkit-serve` 命令入口、pytest 配置 |
| `requirements.txt` | 等价的依赖清单（供不使用 pip install -e 的场景） |

```bash
# 两种安装方式等价（setup 脚本内部执行第二种）
pip install -r requirements.txt
pip install -e .            # 可编辑安装，开发时修改代码即时生效
```

依赖拆分策略：

- **技能模块 / 公共层**：零第三方依赖（纯标准库），可在任何 Python 3.10+ 环境直接运行。
- **服务模块**：仅需 `fastapi / uvicorn / pydantic / pyyaml / httpx`。

## 2. 环境变量定义

命名约定：`DEVKIT_<字段名大写>`。来源与优先级：

```
内置默认值 < config/config.yaml < .env 文件 < 进程环境变量（最高）
```

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DEVKIT_HOST` | `127.0.0.1` | 服务监听地址（部署到服务器改为 `0.0.0.0`） |
| `DEVKIT_PORT` | `8000` | 服务端口 |
| `DEVKIT_API_KEYS` | `dev-key-001,dev-key-002` | 鉴权密钥列表（逗号分隔；生产环境用强随机值） |
| `DEVKIT_WORK_DIR` | `.runtime` | 运行时数据根目录（构建产物/部署记录/日志） |
| `DEVKIT_LOG_LEVEL` | `INFO` | 日志级别 |

示例（`.env`）：

```bash
DEVKIT_HOST=0.0.0.0
DEVKIT_PORT=8080
DEVKIT_API_KEYS=prod-key-abc123,prod-key-def456
DEVKIT_WORK_DIR=/var/lib/devkit
DEVKIT_LOG_LEVEL=INFO
```

`.env` 解析器为自实现（`devkit_common/envfile.py`，零依赖），支持注释、引号、空值。

## 3. 配置文件模板

- `.env.example` → 复制为 `.env`（本地密钥与端口）
- `config/config.yaml.example` → 复制为 `config/config.yaml`（结构化管理，字段与 Settings 一一对应）

```yaml
# config/config.yaml
host: 127.0.0.1
port: 8000
api_keys:
  - dev-key-001
  - dev-key-002
work_dir: .runtime
log_level: INFO
```

> 运行时统一由 `devkit_common/settings.py::get_settings()` 加载（进程内缓存单例），
> 技能模块与服务模块共享同一份配置，避免各模块自行读环境变量导致漂移。

## 4. 一键脚本（跨平台）

| 脚本 | 用途 | Linux/macOS | Windows |
| --- | --- | --- | --- |
| 初始化 | 创建 venv + 装依赖 + 生成 .env + 自检 | `./scripts/setup.sh` | `powershell -ExecutionPolicy Bypass -File scripts/setup.ps1` |
| 启动服务 | 读取配置并启动 uvicorn | `./scripts/dev.sh` | `powershell -ExecutionPolicy Bypass -File scripts/dev.ps1` |
| 环境自检 | 打印能力清单 + 健康检查 | `./scripts/verify.sh` | — |

也可以使用 Makefile 快捷命令（Linux/macOS）：

```bash
make setup    # 初始化
make dev      # 启动服务
make test     # 全量测试
make demo     # 端到端演示
make verify   # 环境自检
```

## 5. 可复现性保证

1. **锁定解释器**：`requires-python = ">=3.10"`，全部代码兼容 3.10–3.14。
2. **隔离依赖**：所有脚本强制使用 `.venv`，不污染系统 Python。
3. **运行时目录**：构建产物/部署记录/日志统一落在 `DEVKIT_WORK_DIR`（默认 `.runtime/`，已 gitignore）。
4. **零配置可跑**：不配置任何东西也能 `setup → dev`（默认开发密钥），配置只是按需覆盖。

## 6. 验证脚本做了什么（setup.sh 摘要）

```bash
python3 -m venv .venv                          # 1. 虚拟环境
source .venv/bin/activate
python -m pip install -r requirements.txt -q   # 2. 依赖
python -m pip install -e . -q
[ -f .env ] || cp .env.example .env            # 3. .env 模板
python -m pytest tests/test_skills.py tests/test_services.py   # 4. 自检
```
