## 1. 语义：为什么是"吸附进安全区"，而不是"整体平移"

面板上的标签写的是 **「安全区域 (异形屏避让)」**（`prop.screen.safe.area`）⇒ 目的就是**别把 UI 放到
刘海/圆角底下**。据此定的导出语义：

- **内容区 ＝ 安全区**：生成代码开头声明内容区 `(Left, Top)–(W-Right, H-Bottom)`；
- **控件吸附**：只把**越界**的控件夹进内容区（位置夹、**尺寸不动**）；本来就在区内的**一个字节都不动**；
- 控件比内容区还大 ⇒ 只能贴左上，并在代码里留注释（不缩尺寸、不静默丢控件）；
- **屏幕尺寸与背景不动**（背景本来就该铺满整屏；避让只约束控件位置）。

⚠ **没有采用"整体平移 (Left, Top)"**：那会把一个**本来就画在安全区内**的界面也整体推一下，
属于没有必要的位移；吸附只对**违规**的控件动手。

## 2. 生成物长什么样

```c
    // 安全区（异形屏避让）：内容区 (10, 20)–(770, 440)，越界控件会被吸附进来
    ...
    // 安全区吸附：(5, 5) → (10, 20)
    lv_obj_set_pos(obj_outside_left_top, 10, 20);
    ...
    lv_obj_set_pos(obj_inside, 100, 100);          // 区内控件原样
    lv_obj_set_size(screen, 800, 480);             // 屏幕尺寸不内缩
```

## 3. 地基：**默认 ⇒ 零影响**

| 场景 | 生成物 |
|---|---|
| 无工程（`project == null`） | 与从前**逐字节相同**，且**连"安全区"三个字都没有** |
| 有工程但内边距全零 | 与"无工程"逐字节相同 |

这条不变量保证这次改动**不会悄悄改掉既有工程或既有判据的产物**（默认 0 内边距 ⇒ 一行不变）。

## 8. 阶段 228：`#98` 进导出的**第二半** —— DPI ⇒ 几何整体换算

用户点的三件事里最后一件是"**字号/尺寸换算**"。这一阶段把 `DpiScale` 接进生成物。

### 8.1 语义：**几何量乘、语义数值不乘**

| 类别 | 例子 | 乘 `DpiScale`？ |
|---|---|---|
| **几何量** | 控件 `X/Y/Width/Height` · 屏幕尺寸 · 背景图尺寸 · 折线点 · **字号**（内置档位与字体资产变体名）· 圆角/边宽（走同一个格式化器） | ✅ |
| **语义数值** | `ValueScaleFactor`（`// Value display: … scale=2 …`）· 阈值 · 动画时长/参数 | ❌（乘了就是错的） |

实现上**只有一个闸门**：新增 `CDim(double)`（＝ `CNumber(value * _dpiScale)`）用于几何站点，
`CNumber` 保持"原样格式化"给语义数值。默认 `DpiScale = 1.0` ⇒ `CDim` 与 `CNumber` **逐字节相同**。

> ⚠ **注释用设计空间、代码用设备空间**：`// 安全区吸附（设计空间）：(5, 5) → (10, 20)` 配
> `lv_obj_set_pos(obj, 15, 30)`（DPI 1.5）。设计师看注释能直接对上画布，代码则是设备像素。

### 8.2 判据 10 条（`DpiScaleExportTests`）

默认 DPI=1 / 无工程 ⇒ **逐字节零影响** · 位置与尺寸换算（1.5× ⇒ 10,20 → 15,30；100×40 → 150×60）·
屏幕尺寸换算（2× ⇒ 800×480 → 1600×960）· **字号**换算后再比较内置档位（20 × 1.5 = 30 > 14 × 1.5 = 21 ⇒ 16）·
**字体资产变体名**里的字号换算（`font_x_20` → `font_x_30`）· 折线点换算 · 脏数据（DPI ≤ 0）按 1 且不出现
`Infinity`/`NaN` · **语义数值不换算**（`scale=2` 不许变成 `scale=4`）· 安全区与 DPI 组合
（**先在设计空间吸附，再按 DPI 换算**）。
