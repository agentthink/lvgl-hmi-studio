# 行为面覆盖 ＋ 登记册复核：一本可复用的手册（阶段 211~259 两次战役的收成）

> 这本手册回答两个**同类**的问题：
> ① **登记册上的结论还成立吗**（阶段 230~246：十二批全量复核）；
> ② **这个按钮/这条接线有没有人看着**（阶段 247~259：行为面残余收口，86.6% → **96.1%**）。
> 两次战役各自沉淀出一套流程与一批陷阱，**踩过的坑都写在这里**，目的是让下一个人不必重走。
> 登记册里的账见 `docs/2026-09-17-open-items-register.md` 的 §146~§175；本手册只讲**方法**。

---

## 1. 战役一：登记册十二批复核（阶段 230~246）

### 1.1 方法：六步

| 步 | 做什么 | 为什么 |
|---|---|---|
| **找锚点** | 每条结论都要有一个**能在今天的代码里跑/读到的锚点**（文件名 ＋ 行号 ＋ 可 grep 的字面量） | 没有锚点的结论无法复核（`#20` 的"无一读产品源码"就是这么假的） |
| **对数** | 把账里的**数字**重新数一遍（行数、条数、partial 数、判据文件名） | 读数过期是本仓**最高频**的失真（§159 的 ①） |
| **分半** | 长状态格要**分头尾**读：头部往往是旧的、尾部才是结论 | 8 次"头部过期"都栽在这（§154/§157/§158） |
| **认边界** | 区分"缺陷"与"判据口径的边界/环境事实" | 把边界当缺陷改，会把产品改坏（`#76` 误诊就是） |
| **解结构** | 用**结构解析**（表行格数、id 唯一性）而不是肉眼扫 | 4 处坏行（未转义竖线/缺列）肉眼扫不出来（§150） |
| **重跑环境** | 环境类事实要**当场重测**（`df`、`du`、`touch`、grep 日志） | 环境会变（`#31`/`#33`/`#58`） |

### 1.2 结论：失真**不是一种病，是八种**

| 类 | 例子 | 怎么抓 |
|---|---|---|
| ① **读数过期** | `#1` partial 12→17 · `#19` 4299→4512 · `#35` 1266→1109 | 对数 |
| ② **证据句失真** | `#20`"无一读产品源码"实测 91 个文件 | 拿证据句去 grep |
| ③ **行结构坏** | `#61j`/`#89` 未转义竖线；`#76`/`#78` 状态粘进"项"格 | 结构解析（格数=表头格数） |
| ④ **处置过期** | `#45`"独占进程规避"在阶段 148 就被撤销 | 回代码看现状 |
| ⑤ **头部过期** | `#61t`/`#61x`/`#71`/`#73`/`#92`/`#96`–`#98` | 分头尾读 |
| ⑥ **环境前提过期** | `#58` 沙箱不再是 root · `#31` 门禁自己绕开 NuGet 只读缓存 · `#33` `/tmp` 10 MB→32 GB | 重跑环境 |
| ⑦ **编号冲突** | `#100`：早期编号按节独立 ⇒ 28 个 id 跨节多义 | 全册 id 唯一性 |
| ⑧ **缺行** | `#57`/`#86` 根本不在 §4 表里（只在章节正文里） | "该在哪个表"的问题要先问 |

🩸 衍生的一条：**「更正记在隔壁」** —— `#76` 撤销了对 `#72` 的失败归因，但 `#72` 自己一直挂着被撤销的结论
（§161）。⇒ 改一行的结论时，**把所有写过同一件事的地方一起改**。

### 1.3 处置纪律三条

1. **就地改要保留原文**：把头部改成 `✅ 已闭环（阶段 XXX） —— ` ＋ 原文照旧，别删历史（原文本身是证据）。
2. **收口必须写证据**：不是"看起来做完了"，而是**锚点 ＋ 读数**（哪条判据、哪个文件、哪次读数）。
3. **失效登记要关掉**：三条"失效登记"（`#9`/`#31`/`#33`）是**关掉并写明为什么不再成立**，不是留着。

## 2. 战役二：行为面残余收口（阶段 247~259）

### 2.1 三层结构：先搞清"你要判的那张面属于哪一层"

| 层 | 判据文件 | 判什么 | 面的筛法 |
|---|---|---|---|
| 第一层 菜单 | `MainWindowMenuInvocationUiTests` | 点菜单项 ⇒ 弹了什么 | 菜单项清单 |
| 第二层 工具条 | `MainWindowToolbarInvocationUiTests` | 同上（工具条） | 工具条按钮 |
| 第三层 对话框内 | `DialogInnerInvocationUiTests` | **从菜单打开的宿主窗**里的按钮 | 宿主窗内具名按钮（**双向差集**） |
| 第四层 停靠面板 | `DockPanelInvocationUiTests` | 停靠面板内按钮 ⇒ 弹窗层数 | ⚠ **只收名字以 `Btn` 开头的** |
| 第五层 宿主效果 | `HostButtonEffectUiTests` | 宿主里每个按钮**点下去改了什么** | 宿主窗内**所有**具名 Button（含 `ToggleButton`） |
| 专题判据 | 见 §2.3 | 上面四层都装不下的**单张面** | 判据自带声明表 ＋ 双向差集 |
| 名字级探针 | `scripts/face-residual.py` | "这个按钮名有没有被任何判据文件提过" | 全仓 `.axaml` 的具名动作控件 |

🩸 **第四层的面按 `Btn*` 前缀筛**（阶段 251 才查明）：12 个停靠面板里有 **6 个**视图的动作控件
（共 **29** 个）**不在它面内**。⇒ 这类"够不到"的视图必须由**第五层**或**专题判据**托底；
`HostButtonEffectUiTests.DockPanelsOutsideTheBtnPrefixedFace_MustBeHostedOrExplicitlyWaived`
把这份清单钉住了（4 个进第五层 · 1 个判过不做 · 1 个进专题判据）。

### 2.2 口径纪律三条（引数字之前先读这三条）

1. **引数字必须带来源工具名**：`face-residual.py` 是**按钮类 · 名字级**（残余 10 格）；第四层那张
   `OutsideFaceCensus` 是**选择类 · 接线控件级**（1 视图 / 31 控件）。两边**曾经都出现过 `63`** 这个巧合同数。
2. **残余个数 ≠ 缺口大小**：`PropertyPanelView` 残余最多（10/15），但阶段 118 判定**不扩**
   （数据面已由 `PropertyPanelWiringTests` 判过、写入是**批量**的 —— 与第五层"未声明分量一字不变"正面冲突）。
   账本的排序口径 ≠ 覆盖缺口的大小。
3. **名字级只能排优先级**：说"这个按钮被判过"必须回到那一层的**声明表**点名核对；
   而且**一个判据会清掉别处同名的格**（阶段 253 实测：补一个判据掉 8 格，其中只有 7 格是那个视图的）。

### 2.3 判据形状库（七张专题判据的模板）

| 形状 | 代表 | 要点 |
|---|---|---|
| **面双向差集 ＋ 桶表 ＋ 理由** | 全部十张 | 少一个（被删/改名）与多一个（没分类）**都红**；`Never` 的理由要写够（≥10 字） |
| **事件观测** | `AiChatPanelView`（第五层） | 处理器只 `Invoke` 公开事件时，订阅它拿载荷；⚠ 构造期往静态总线的转发判不到 |
| **布景（Arrange）＋"不许替处理器做事"** | `AuditLogView` | 布景只许动**输入面**分量；用 `LoadAuditLogFromFile`（不抬事件）而不是 `RecordAudit`（会抬事件、面板自己就加进去了） |
| **`ShowDialog` 判返回值契约** | `ReportColumnDialog` | `Close(SelectedKeys())` vs `Close(null)` —— 调用方判的就是 `null ⇒ 取消`，**空集冒充不了** |
| **剪贴板出口** | `ValidationResultView` | 读法 `ClipboardExtensions.TryGetTextAsync()`（`Avalonia.Input.Platform`）；`SetTextAsync` 是 fire-and-forget ⇒ **轮询等待、不能阻塞** |
| **沙箱里的真服务** | `LoginDialog` | 用真 `AuthenticationService`（`CreateUser` 造用户）判"界面 ⇒ 服务 ⇒ 回界面"整条链，**不 mock** |
| **只构造不 `Show()`** | `BuildRunDialog` / `LuaHelpDialogUiTests` | 窗的 `Loaded` 里有真动作（跑构建/挂死布局）⇒ 不显示也能 `RaiseEvent` 驱动 XAML 挂上的处理器 |
| **注入缝（internal ctor）** | `AiIconDialog`(209) · `VariableImportView`(254) · `FontSubsetView`(258) | 把**平台边界**（文件选择器/生成源）换成委托 ⇒ 判据能驱动整条链；`internal` ⇒ **不动公共构造**（否则动到 `WindowProductionPathUiTests` 的双路径元检查） |

**加缝的判准**（什么时候值得动产品）：当"没有缝就只剩早退档"时 —— 例如
`_selectedFilePath` 只能由平台选择器写入 ⇒ 解析/导入两条腿**原理上够不到**、只能记 `Inert`（记了个寂寞）。
加缝时：① 抽出共用私有方法（两条路径**共用同一段产品代码**）；② 传 null 时与加缝前**逐字相同**；③ 写在 xmldoc 里说明理由。

### 2.4 陷阱清单（都踩过，每条都付了门禁一次红）

| 陷阱 | 症状 | 正解 |
|---|---|---|
| 程序化写 `TextBox.Text` **不触发** `TextChanged` | 搜索/输入腿恒不生效 | 走 `ControlWiringFace.Write`（写文本 ＋ **补发** `TextChangedEvent`）；裸 `TextBox` 实测 `set=0 / Clear=0 / 补发=1` |
| fire-and-forget 的异步出口 | 立刻断言读到旧值 | **轮询等待**；⚠ 不要 `.GetAwaiter().GetResult()`（headless 同线程 ⇒ **死锁**） |
| `Show()` 会触发 `Loaded` 里的真动作 | 真跑构建/布局挂死 | 能只构造就不 Show（本仓有现成先例） |
| 读数在点击**之后**才写 | "默认态"被写成"点完态"（我犯了 3 次） | 点击**前**把初值存进变量，再在读数里引用 |
| 门禁**警告即失败** | 临时构建只 `grep 错误` ⇒ 漏掉 `CS8602` | 临时构建也看警告；**门禁才是准的仪器** |
| 测试不得用 `Path.GetTempPath()` | `TestTempDirUsageGuardTests` 点名两行 | 用 `DataRootSandbox` 根下的名字 |
| `ToggleButton`/`CheckBox` **也是** `Button` | 面把复选框算成按钮 | 面要按**精确类型**收：`b.GetType() == typeof(Button)` |
| `Panel.Children` 的元素**不进逻辑树** | `GetLogicalDescendants` 找不到动态子控件 | 用 `FindControl<Panel>` ＋ `panel.Children` |


② 逐支**还原并核对 sha256 逐字节相同**；③ 期望红要**点名到具体 fact**（`"[FAIL]" 行里含那个方法名`），
避免"随便红一个"也算过。

## 3. 两条账怎么互相喂

```
登记册复核 ──(发现"这条结论失效/缺行/编号冲突")──▶ 面覆盖的候选
面覆盖收口 ──(每条残余都要写"为什么留开/为什么不扩")──▶ 登记册的新锚点
```

- 复核找出的"失效登记"会变成**面覆盖的选题**（`#39` 的残余清单就是这么来的）；
- 面覆盖的每条豁免都要写**口径边界**（`PropertyPanelView` = 判过的不做），这反过来成了复核时的锚点。

## 4. 这套方法**测不出**什么（如实划界）

1. **产品的"该不该"**：判据只回答"点下去会发生什么"，不回答"这个行为对不对"（那是产品决策，见登记册 §2）。
2. **真机/真外部工具**：真在途构建、真烧录、真设备行为 —— 只能记 `Never` ＋ 写明理由。
3. **判据自身的口径边界**：名字级探针看不见"提过名字但没真驱动"；层级判据看不见"跨层的重复记账"。
   这些边界必须**写进判据的 xmldoc**，否则下一个人会把它们当缺口。
4. **首跑就绿 ≠ 判据有效**：每条新判据都要有**负控**（改产品 ⇒ 必须红）才算立住。
