# 智数 HMI 工业化开发计划

> 目标：把设计器—代码生成—模拟器—T113 实机链路收敛为可重复验证、可交付的嵌入式 HMI 平台。

## 一、执行原则

1. 先闭环、后扩展：优先修复已有能力在 CodeGen、模拟器和固件之间的不一致。
2. 质量门禁优先：新增功能必须同时提供模型、生成器、运行时和测试证据。
3. 生成结果可追溯：导出记录项目版本、生成器版本、LVGL 版本和 Git commit。
4. 悬空引用、权限绕过、资源超限和关键桩实现不得静默进入生产工程。

## 二、版本路线图

| 版本 | 周期 | 交付目标 |
|---|---:|---|
| v2.2 | 2-3 周 | 质量基线、CodeGen 验证、生成产物治理 |
| v2.3 | 3-4 周 | 模拟器变量、绑定、动作、报警和趋势闭环 |
| v2.4 | 4-6 周 | T113 运行时、触摸、RS485、更新回滚 |
| v2.5 | 5-7 周 | 报警、趋势、权限、审计、通信诊断 |
| v2.6 | 4-6 周 | 工业对象库、模板版本、点表导入 |
| v3.0 | 8-12 周 | AI 生成、Web 诊断、历史报表、驱动生态 |

## 三、Phase 0：质量基线（立即执行，P0）

- [ ] 新增并维护 docs/project-status.md，记录当前真实验证结果。
- [ ] 建立 scripts/verify.ps1 与 Linux 等价入口，统一 build/test/静态验证。
- [ ] 清理 CommunicationConfig、XAML 资源等构建警告。
- [ ] 修复旧测试断言，优先验证行为而非完整注释文本。
- [ ] 清理或重新生成 sim-output、测试输出和固件临时产物。
- [ ] 为每次生成记录 generator/LVGL/commit 元数据。

验收：0 Error、0 Warning、全量测试通过；验证脚本可重复执行。

## 四、Phase 1：CodeGen 可靠性（v2.2）

- [ ] 校验控件/屏幕 ID、变量、UDT、表达式、资源、动作和通信引用。
- [ ] 校验 C 标识符、LVGL API、头文件、定时器和资源引用。
- [ ] 建立 HMI1xxx 错误、HMI2xxx 警告分类。
- [ ] 悬空画面、变量、脚本引用默认阻止生产导出。
- [ ] 建立至少 10 个 Golden Project。
- [ ] 增加生成、CMake 编译和文件完整性测试。

## 五、Phase 2：模拟器闭环（v2.3）

- [ ] 统一模拟变量、原始值、工程值、质量码和更新时间。
- [ ] 补齐 Label、Bar、Slider、Gauge、Knob、Led、Switch、CheckBox 绑定刷新。
- [ ] 补齐颜色、可见性、透明度、文本和几何属性绑定。
- [ ] 验证页面切换、变量写入、位操作、登录、报警、趋势和脚本。
- [ ] 增加变量/通信/权限/脚本调试面板。
- [ ] 增加自动冒烟测试和 8 小时稳定性测试。

## 六、Phase 3：T113 实机闭环（v2.4）

- [ ] 建立显示、触摸、RS485、启动、更新、回滚测试矩阵。
- [ ] 验证 UART 方向控制、超时、CRC、重试、断线重连和质量码。
- [ ] 验证报警、趋势、登录、权限、审计的设备端运行时。
- [ ] 验证内存、帧率、开机时间、触摸延迟、通信周期和长稳。
- [ ] 完成 UDISK 持久化、热更新、失败回滚和日志轮转。

## 七、Phase 4：工业核心能力（v2.5）

- [ ] 报警触发、延迟、死区、确认、复归、历史和联动。
- [ ] 趋势采样、缓存、查询、CSV 导出和断电策略。
- [ ] 登录→角色→动作校验→拒绝提示→审计记录。
- [ ] 通信状态、延迟、失败、重连、质量码和原始报文诊断。
- [ ] OPC UA 节点浏览、订阅、重连、认证和证书基础支持。

## 八、Phase 5/6：对象库与平台化

- [ ] Motor、Pump、Valve、Tank、PID 标准 Faceplate。
- [ ] 模板分类、缩略图、参数、依赖、版本和迁移。
- [ ] CSV/Excel/JSON 点表导入并生成变量和 UDT。
- [ ] AI 生成画面、变量、报警和模拟场景，必须经过验证和用户确认。
- [ ] PC/服务器历史数据库、报表和 Web 设备诊断。
- [ ] 驱动插件 SDK、固件签名、安全升级和密钥管理。

## 九、质量门禁

每次提交：dotnet build、dotnet test、CodeGen 静态验证、Golden Project 完整性检查。
每个版本：Golden Project CMake 编译/模拟器冒烟、100/500/1000 控件性能、1000 绑定压力、T113 硬件矩阵、8 小时稳定性、发布包 hash 与回滚验证。

## 十、立即执行顺序

1. 记录当前 build/test 真实结果。
2. 创建 project-status.md。
3. 新增统一验证脚本。
4. 修复首个构建警告或失败测试。
5. 建立基础控制 Golden Project。
6. 补齐一个控件的设计器→CodeGen→模拟器→固件链路。
7. 回填验证结果并扩展到其余控件。

完成定义：功能必须同时有模型、UI、CodeGen、运行时和测试证据；生成工程可编译运行；差异、资源、权限、错误和日志策略均有记录。
