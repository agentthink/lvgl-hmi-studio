## 1. 🩸 先更正：原登记「全仓 grep 0 命中任何 HTTP/WebSocket/远程通路」**口径失真**

实测（2026-10-01，阶段 263）—— **设备侧已经有**：

| 事实 | 锚点 |
|---|---|
| MQTT 3.1.1 客户端（QoS0；主题上限 32；RX 缓冲 512 B；重连 5 s；`publish`/`subscribe`/`keepalive`/状态机） | `firmware/t113/app/comm/mqtt_client.c:20-34`、`comm/mqtt_client.h:19-38` |
| **变量变化上行**：comm 线程每 ~1 s 扫一遍 MQTT 驱动的绑定，**值变化才发**；主题 `HMI_MQTT_TOPIC_PRE + "/val/" + 变量名`，payload `%g`（**纯数值：无时间戳、无质量位**），retain=0 | `firmware/t113/app/runtime/variable_table.c:453-472` |
| 连接参数**运行时可下发**：`/mnt/UDISK/hmi/comm_config.ini`（host/port/client_id/user/pass/keepalive），优先级 ini > `generated_comm.h` > `runtime_config.h` | `firmware/t113/app/comm/comm_core.c:29-34,175-219` |
| OTA 已有 HTTP 通道 | `firmware/t113/tina/package/hmi-runtime/files/hmi_ota.sh:20-21` |

**编辑器侧（⚠ 我第一版在这里写错了，当场更正）**：`src/Hmi.Communication.Builtin/MqttDriver.cs` 是**设计期/代码生成**驱动 —— 它只给配置模板（broker/port/clientId/…）并 `GenerateRuntimeCode()` **发出设备侧 C 代码**（`mqtt_connect(...)` / `mqtt_subscribe(...)`）；**编辑器自己运行时并不说 MQTT**（没有 `MqttRuntimeDriver`，与 Modbus 不同）。⇒ 「设备说 MQTT、编辑器只说它该怎么配」——**远程端（订阅方）是纯新增交付物**，这一点反而更支持本提案的第 1 条缺口。

⇒ 原话的范围太大了。缺的**不是通路**，而是这四件事：

1. **远程端（展示层）** —— 没有任何远程 UI/服务；
2. **主题与 payload 契约** —— 现在的 `%g` 纯数值既无时间戳也无质量位，且主题前缀只有一个宏；
3. **安全模型** —— 设备侧无 TLS、无主题 ACL；
4. **双向写与审计** —— 只有上行、没有 `/cmd/` 通道与授权/审计接线。

（这是 §159 的「证据句失真」类第 4 次：**结论方向没错** —— 那时确实没有远程访问能力 ——
但**证据句本身不成立**，会误导下一个人以为"连 socket 都没有"。）

## 2. 现状能力盘点（四块可直接复用）

| 能力 | 现状（锚点） | 远程访问里能直接用的 |
|---|---|---|
| **上行** | MQTT 变化发布已有（`variable_table.c:453`） | 只读镜像 / 报警 / 心跳的骨架 |
| **认证与角色** | 设备端用户表 ＋ 角色（`RuntimeUser` / `RoleId`；测试用 fixture 是编辑器生成器的**真实产物**，由 C# 侧逐字节守卫）＋ 权限动作链（`firmware/t113/tests/hmi_actions_permission_test.c`） | 远程命令的**授权判定**复用同一模型 |
| **审计** | 设备 `hmi_log`（会话超时/审计落盘有测试）＋ 编辑器 `AuditLogView` | 远程写操作的审计落点 |
| **升级** | OTA（HTTP） | 远程端固件/HMI 包升级链路 |

**缺口**：TLS（设备侧未链 mbedTLS）· 主题命名空间约定 · 报警事件上行 · 在线状态/遗嘱（LWT）·
远程端 UI · 双向命令通道。

## 3. 三档架构

### 档 A：**复用 MQTT 上行 ＋ 远程订阅端**（只读优先）——推荐
- **设备**：已有发布不动骨架，新增 ① 主题命名空间 `<prefix>/<site>/<device>/{val,alarm,status}`
  ② payload 契约（JSON 或紧凑 `v,t,q`）③ 报警**事件**发布 ④ LWT 在线状态。
- **远程端**：Web（MQTT over WebSocket）或桌面客户端。⚠ **编辑器不能「兼任」**：它没有运行时 MQTT 客户端
  （`MqttDriver` 只生成设备代码）⇒ 若要让编辑器当远程端，得**先补一个运行时 MQTT 客户端**（另一笔工作量）。
- **工作量**：设备 3–5 人日；远程端 5–10 人日；安全见 §4 另算。
- **风险**：低 —— 不碰 LVGL UI 线程、不碰渲染。
- **依赖**：一个 broker（现场局域网 Mosquitto 即可）。

### 档 B：**设备侧 HTTP/WebSocket 网关**（不依赖 broker）
- 直连设备 IP 的只读 Web UI ＋ WS 实时推送；要在 C 里引入/自写 HTTP 栈，**TLS 证书管理**复杂。
- **工作量**：15–25 人日；**风险中高**（内存/稳定性/攻击面都压在设备上）。

### 档 C：**云平台 / 多站点**
- 档 A ＋ 云侧 broker ＋ 设备管理（影子/OTA/多租户/看板）。工作量最大，**可以后置**。

**推荐路径**：**A →（按需）C**；**B** 只在"客户现场不许出网、也不许装 broker"时才考虑。

## 4. 安全模型（缺一不可，逐条给判据面）

| 面 | 方案 | 判据面（机械可判） |
|---|---|---|
| **传输** | TLS 优先**由 broker 终结**（设备侧省 mbedTLS 体积与证书轮换）；若必须设备终结，先评估 mbedTLS 体积 | `comm_config.ini` 增加 `mqtt.tls` 开关 ＋ 端口约定；**负控**：关 TLS 直连 8883 必须失败 |
| **授权** | **主题级 ACL** ＋ 设备端**角色**判定（复用 `hmi_actions_permission_*` 模型） | 未授权主体写 `/cmd/` ⇒ 设备拒绝 ＋ 审计一条 |
| **认证** | 复用设备用户表（口令已经是 `hmi_crypto` 哈希）＋ 会话；远程端**不落地长期凭据** | 与 `hmi_actions_credential_test` 同源 |
| **审计** | 设备 `hmi_log` ＋ 编辑器 `AuditLogView` | 每条远程写 = 一条审计（主体/时间/旧值/新值） |
| **失效** | 命令带 **TTL ＋ 幂等 id**；离线命令不排队 | 过期命令必须被丢弃（判据） |

## 5. 里程碑与判据面

| # | 里程碑 | 交付 | 判据面 |
|---|---|---|---|
| **M1** | **主题/payload 契约 ＋ 两端解析器**（**建议先做：任何档都要**） | 设备侧 `hmi_mqtt_format_*` 纯函数 ＋ 编辑器侧解析器 ＋ 一份契约文档 | `firmware/t113/tests/hmi_comm_test.c` 逐字节断言主题与 payload（含长主题/长变量名边界）；C# 侧同源解析单测；**同一组样例在两侧都过** |
| M2 | 报警/状态上行 | `alarm` / `status` 主题 ＋ LWT | 主机测试用**假 broker**（本地 socket 监听）断言报文序列 |
| M3 | 远程只读端 | Web 订阅 ＋ 展示（只读） | 编辑器侧 loopback HTTP 判据；前端只做契约快照 |
| M4 | TLS/ACL/认证 | broker 终结 TLS ＋ 主题 ACL ＋ 设备侧角色判定 | §4 三行的负控 |
| M5 | 双向写 ＋ 审计 | `/cmd/` 主题 ＋ 权限 ＋ 审计 ＋ 幂等/TTL | 未授权拒绝 · 过期丢弃 · 审计一条 |
| M6 | 现场试点（单站点） | —— | 人工（本册 §0.1 的发布门槛不覆盖它） |

**M1 为什么排第一**：三档架构**都要**它；它**今天就能机械判**（主机测试 ＋ C# 单测，无外部依赖）；
而且它顺手把"payload 只有 `%g`"这个既有缺口（无时间戳/质量位）解决掉。

## 6. 需要你拍板的四个问题（**已拍板，2026-10-01 阶段 270**）

> **拍板结果**：① **可写（C2=③ 全可写）** —— 远程可写变量/动作 ⇒ §4 安全模型**全套成为必经**
> （主题 ACL · 认证 · 审计 · 命令 TTL ＋ 幂等 id），M4/M5 不再是"可选"。② 拓扑：**先局域网**（C3 待定云）。
> ③ **TLS 由 broker 终结**（C4，设备侧零改动）。④ M2 的**主题与 payload 沿用 M1 形状**
> （`<prefix>/alarm/<id>`、`<prefix>/status`；`key=value;`）—— 不另立站点层级、不换 JSON。



| # | 问题 | 影响 |
|---|---|---|
| 1 | **只读，还是可写？** | 只读：工作量与风险小一个量级；可写：必须配齐 §4 全套（ACL/认证/审计/TTL） |
| 2 | **现场局域网 broker，还是云？** | 决定走档 A 还是 A＋C |
| 3 | **TLS 终结在哪？** | broker 终结 ⇒ 设备零改动；设备终结 ⇒ 先评估 mbedTLS 体积与证书轮换 |
| 4 | **远程端形态？** | Web / 编辑器兼任 / 手机 App —— 决定 M3 的交付物 |

（另需背景信息：站点数量级、现场是否允许出网、运维方能不能部署 broker。）
