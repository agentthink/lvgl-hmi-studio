## 1. 先对齐现状（实测锚点）

| ISA-18.2 的要素 | 本仓现状 | 结论 |
|---|---|---|
| **状态模型**（Normal / Unack / RtnUnack / Ack） | `AlarmEngine.cs:10-14` 的类注释就是四态迁移：`Inactive → (条件满足) → Active → (确认) → Acknowledged → (条件解除) → Returned`，并区分"条件解除时是否需确认"两条路径；`AcknowledgeAlarm` **只允许 `Active`**（`:163-171`） | **已有**（差一个显式的 RtnUnack 名，见缺口 ㊁） |
| **设备侧同款状态** | `CodeGenerator.Alarm.cs` 为每条报警生成 state 0/1/2/3 与 `RequiresAck` 分支（`:176-185`）、`pending_since` 延时挂起（`:150`） | **已有** |

| **报告框架** | `ReportTable`/`ReportExporter`（CSV / 自包含 HTML / xlsx）＋ 报表设计器 | **已有** |
| **职责字段**：原因 / 响应 / 后果 | `AlarmConfig`（8 个字段：Id/Name/Description/Severity/GroupId/RequiresAck/IsEnabled/Condition/ScriptId/LinkedControlId）**没有** | **缺口 ㊀** |

**后半句需要更正**：状态机与设备侧状态迁移**已经实现**，缺的是**优先级/搁置抑制/KPI**。

## 2. 三段切片（每段独立交付、独立判据）

### 切片 ㊀ 职责字段（最小、最安全）—— **建议先做**

- **模型**：`AlarmConfig.Cause` / `.Response` / `.Consequence`（`string?`，可空）。
- **消费点（两处，缺一不可 —— 只加字段不改消费＝死字段，本仓有守卫盯这个）**：
  1. `AlarmConfigView` 面板：三个输入框可编辑并**写回模型**；
  2. **主报警表导出**（新报表 `AlarmPhilosophyReport`，走既有 `ReportExporter`）：
     列 = `ID / 名称 / 级别 / 优先级(切片㊁) / 原因 / 响应 / 后果 / 关联控件 / 是否需确认`。
     它是工程交付物（"报警哲学文档"）的机读版，ISA-18.2 实施里本来就要交。
- **判据面**：① 模型 JSON 往返（含 `null` ⇒ 空串口径）；② 报表**列序与内容逐字节**（含空值策略）；
  ③ 面板写回（字段面双向差集）；④ **旧工程兼容**（缺字段 ⇒ 空，不抛）。
- **估算**：1.5–2 人日。

### 切片 ㊁ 优先级与升级

- **模型/纯函数**：`AlarmPriority`（1–4）＝ `f(Severity, AllowedResponseMs)`；ISA-18.2 的关键点是
  **优先级 ≠ 严重度**（同一个"高"在 10 s 内要响应时比 10 min 的高一档）。
- **消费点**：报警列表排序/着色（编辑器）＋ 切片㊀ 报表的"优先级"列 ＋ 设备侧复用**现有** `severity`
  字段下发（**不改生成协议**，只是把优先级映射进那一位）。
- **判据面**：派生纯函数表驱动（含边界：`AllowedResponseMs` 缺失时的回退）；
  排序**稳定**（同优先级保持原序）；生成协议**不变**（对同一条报警，切片㊁ 前后的 severity 位逐字节相同）。
- **估算**：2 人日。

### 切片 ㊂ 搁置 / 抑制 ＋ KPI

- **搁置**：`AlarmEngine.Shelve(recordId, TimeSpan, by)` ＋ 到期自动解除 ＋ 事件；
  非法迁移必须被拒（**搁置中不允许确认**、已 Returned 不允许搁置、搁置时长有上下界）。
- **抑制**：按组或按条件屏蔽（与状态机分离：抑制是**不产生记录**，不是"产生后隐藏"）。
- **KPI**（从 `AlarmRecord` 序列算，纯函数）：报警率（次/小时）、平均驻留（occurred→returned）、
  抖动（同 alarm 在 N 分钟内重复次数）、Top10（按次数/按驻留时长）。
- **判据面**：状态迁移**矩阵**（合法迁移全过、非法迁移逐条拒）＋ KPI 表驱动 ＋ KPI 进既有报告框架。
- **估算**：3–4 人日。

## 3. 迁移与兼容

- 三个职责字段**可空** ⇒ 旧工程 JSON 直接可读，**不需要迁移脚本**。
- 空值策略（写死并判据化）：导出时**留空列**，不写 `null` / `N/A`；报表脚注注明"未填写"。
- 设备侧：切片 ㊀㊁ **不改**生成协议（㊁ 复用 severity 位）；切片 ㊂ 若要把"搁置"下发设备，
  需先立**契约**（与 `§2-#12` 的 M1 同款做法：先契约、后实现、两端同源样例判据）。
