## 110.1 为什么下一个是这个

阶段 109 的 `SettingsDialog` 是「**一个复选框 ↔ 一个设置项、点一下当场恰好改 1 个分量**」那种设置面。
它回答的是「判据骨架能不能读服务对象」，但回答不了另一半问题：

> 界面上那个控件的值，**是不是当场就落进模型**？

真实的产品代码里，绝大多数设置面板是**两段式**的 —— 改控件只标「脏」，点「应用/确定」才落盘。
`ProjectSettingsView` 正是这个形状，而且它比 `SettingsDialog` 还多一层：

| 维度 | 前三处（107） | `SettingsDialog`（109） | `ProjectSettingsView`（110） |
|---|---|---|---|
| 数据面在哪 | 模型集合计数 | **服务对象**属性 | **工程模型**（`HmiProject` 的 5 个子配置）＋ 窗口列表 |
| 一次点击改几个分量 | 常 2~3 个 | **恰好 1 个** | 10 个复选框**各自 0 个**；`BtnApply` 一次改 **11 个** |
| 面里 `CheckBox` 占比 | 3 / 31 | 19 / 26 | **11 / 19** |
| 「写」是否立即发生 | 是 | 是 | 🩸 **不是**（标脏 ＋ 草稿 **两条**延迟路径） |
| 窗口里有状态栏吗 | 有（`StatusText`） | 没有 | **没有**（同为对话框） |
| 依赖 | 模型 ＋ 工程 | 两个服务（夹具已有） | `WindowDepot.Project`（夹具已有，**本轮夹具一行没改**） |

⇒ **判据骨架仍然一行没动**（`Probe` / `Bucket` / `ClickSpec` / `Check` / `CollectNamedButtons` /
`BucketTables_*`），换的只有 Probe 读法与**桶的处置口径** —— 后者是本阶段的全部内容。

## 110.4 🩸 两段式声明：10 条 `Inert` ＋ 1 条 `Moves` **合起来**才是一个完整命题

这是本阶段唯一的新东西，也是这个宿主值得单开一刀的理由。

10 个复选框的接线是 `AttachChangeHandler(ChkXxx)`：

```csharp
else if (ctl is CheckBox chk)
    chk.IsCheckedChanged += (_, _) => _hasChanges = true;   // ← 只写一个 private bool
```

它们**当场一个模型字段都不写** —— `_hasChanges` 是 private，本层读不到。
它们的值要到 `SaveToProject()` 里才被**读走**：

```csharp
_project.ExportConfig.MergeResources = ChkMergeResources.IsChecked ?? true;   // 这一类，共 10 处
```

所以表里的处置是**两段式**：

| 段 | 声明 | 说出的事 |
|---|---|---|
| ① | 10 条 `Inert`（各自 0 个分量动） | 「点下去**确实什么都没写**」—— 这是**事实**，**不是**「没接线」 |
| ② | `BtnApply` 一条 `Moves`（10 个 bool 全翻 ＋ `用户·模型` 0 → 1） | 「它们的值**真的被读走**了，所以 `_hasChanges` 不是空转」 |

单看任一半都不成立：只有 ① 就分不清「标脏」与「线断了」；只有 ② 就说不出「不点应用就不落盘」。
反向也有实测：**NC3** 给其中一个复选框额外接一条写模型的线 ⇒ ① **当场变红**
（`未声明`的分量「导出·合并资源」从 1 变成了 0）—— 这正是「`Inert` 记的是事实、修好就红」那条机制
在第二个宿主上的再次触发（第一次是阶段 108 修 #64）。

## 110.5 🩸 三条 `Inert` 的成色各不相同 —— 全都写进 `Why`

桶名一样，成因是三件不同的事。写错不会有人打（`Inert` 的 `Why` **免证**，阶段 108 教训），
所以逐条把处理器读了一遍：

| 按钮 | 真实成因 | 类别 |
|---|---|---|
| `ChkRuntimeUserEnabled` | 处理器**真跑了**（`user.IsEnabled = false`、列表重建），但改的是**草稿对象**；本层的两个用户表出口是**列表计数**与**模型计数**，都不反映**单个条目的启用位** ⇒ 未被观测 | 「未被观测」（与阶段 107 的 `BtnSaveAlarm` 同形） |
| `BtnSetRuntimeUserPassword` | 处理器的**第一个分支**就是「`password.Length == 0` ⇒ 只把『需要密码』写进提示行并 `return`」；夹具里没人往 `TxtRuntimeUserPassword` 填过东西（本层没有「先填输入框」的机制） | 处理器提前 `return` |
| `BtnApplySizeToAll` | ⚠ **不是没接线**：`foreach (var screen in _project.Screens)` 确实跑了（`_hasChanges` 标了、按钮文案也改了），但夹具里的屏幕是 `ScreenFactory` 用**同一份** `ScreenDefaultsConfig` 建的 ⇒ 写进去的是**同一个数** | 「写入同值」 |

⚠ 最后一条最容易写错：读法上它是 `Inert`，成因却是**同值**而非没接线。
**哪天夹具让「屏幕尺寸 ≠ 默认尺寸」，这一条就会红** —— 那是对的，改声明即可。
