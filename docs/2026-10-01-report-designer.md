>
> 本阶段（181）＝ 定义批 ＋ **模板内核**（Core 纯逻辑那一半）。App 侧的存储与窗口留下一片。

---

## 1. 现状读数：现在能"设计"什么

| 面 | 现状 | 缺口 |
|---|---|---|
| 列布局 | 阶段 177 的 `ReportColumnDialog` 只能**勾子集** | 顺序＝数据源固定列序、列名＝字典给的、**不保存**（下一次导出从零勾） |
| 时间范围 | 阶段 178/180：快捷档 ＋ 自定义起止日期 | 已够用 |
| 格式 | CSV / xlsx / PDF / HTML ＋ 报表包 | 已够用 |
| 列键 | 稳定标识（`AuditLogReport.ColumnKeys`、`AlarmReport`、`HistoryReport.TimeColumnKey`） | 列键是**投影与判据的对齐依据** ⇒ 任何模板都必须以键为准 |
| 历史报表的列 | **动态**：时间列 ＋ 每个变量一列（列名＝变量 Id） | 存下来的列清单**必须容忍**列的新增/删除 |

⇒ 真正的缺口是四件：**顺序**、**列名**、**隐藏**、**持久化**。前三件是纯逻辑（Core，可判），
第四件是存储（App）。

## 2. 选型：三件都可能被叫"设计器"的东西

| 候选 | 主张 | 取舍 |
|---|---|---|
| **列布局模板**（本阶段做） | 顺序 ＋ 改名 ＋ 显式隐藏 ＋ 持久化 | 复用既有 `ReportTable` 与投影机制；纯函数可判；用户价值直接（"我要的列、我要的名字、下次还在"） |
| 排序 / 分组 / 小计 | 按某列排序、分组小计 | 要动**行模型**（现在一行只是一串字符串），分组小计还要数值类型与口径（分组键、小计格式、空值）⇒ **本阶段不做** |
| 表达式列 / 自定义列 | 像 Excel 那样算一列 | 要"表达式引擎 → 列投影 → 类型推断 → 四种格式的渲染"四件一起动；而且报表是**离线导出**路径，不是运行时 ⇒ 成本极高、**不做** |

**模板引擎仍明确不做**（阶段 172 的选型结论继续成立）：本仓的产物要能**逐字节判**，
把"占位符替换"交给第三方语义得不偿失 —— 报表只需要 标题/生成时间/表头/行 四件。

## 3. 口径决定：模板是**覆盖层**，不是白名单（本阶段最重要的一条）

阶段 177 的 `WithColumns` 是**白名单**（用户当场勾的，一次导出有效）；模板是**长期**存下来的，
若也按白名单，会有一种很难被发现的坏结果：

> 历史数据报表里用户**新加了一支画笔** —— 报表里**永远**看不到它，因为模板里的清单没提它；
> 数据在看板上、导出里没有，**不报错、不提示**。

所以模板只做三件事（`ReportTemplate`）：

1. **顺序**：模板里**列到**的键按模板顺序排在前面，**没列到**的按原序**接在后面**（新列不会消失）；
2. **改名**：条目的 `DisplayName` 覆盖列名，**列键永不变**（键是投影/判据的对齐依据）；
3. **隐藏**：**显式**写 `Hidden = true` 才拿掉（＝"这是我决定的"，而不是"我上次没勾"）。

配套口径（逐条都有判据）：

- `null` / 空模板 ⇒ **恒等**（返回原表本身）："没设模板"不是"什么都不要"；
- 模板里的**未知键忽略**（留着已删掉的变量比抛异常更不容易把用户挡在门外）；
- **重复键第一条生效**（顺序与改名都一样）—— 同一份模板不许给出两种列序；
- **全部列都被隐藏 ⇒ 抛**：静默给一张空表会让用户以为"这段时间没数据"；
- `CsvOverride` **原样带过去**、模板对**它**不生效（历史数据的 CSV 走设备列序 —— 阶段 176 的既有口径）。

**存储两选项的证据对比**（182 的拍板依据 —— 用户选 **A 应用级设置**）：

- **应用级设置**（`App.SettingsService`）：先例是**阶段 165 的面板布局持久化**（`#80`）——
  它是**操作者偏好**，换工程后仍应生效；三面板已能**静态**取到 `App.SettingsService`（零接线改动）。
  代价：`UserSettings` 是 `Dictionary<string, object?>`，嵌套对象读回来是 `JsonElement`
  ⇒ 要放**结构化**值，得给 `Coerce<T>` 加一条"复杂类型走 `JsonSerializer`"的回落（或把模板存成 JSON 字符串）。
- **工程文件**（`HmiProject`）：强类型、天然往返；代价是动工程 schema
  （有往返/逐字节判据与 CodeGen 消费面），而模板描述的是**运行数据的视图**（审计/报警/采样都不在工程里）。

## 5. 诚实边界（本阶段不做，且不假装做了）

- 模板只管**呈现**：过滤仍在范围对话框、行数封顶仍在 `HistoryReport`（`DefaultMaxRows`）；
- **一个数据源一份模板**（不做多份命名模板、不做"共享模板文件"）；
- 排序/分组/小计、表达式列、模板引擎：见 §2 的取舍，**不做**；
- 模板对 **CSV** 不生效的那一半（`CsvOverride`）如实保留 —— 靠判据钉住，不靠注释。

## 7. 阶段 183：设计器窗口 ＋ 三个面板的入口与套用点

分片计划里的第三片，也是**用户看得见**的那一片。

### 7.1 界面与两条新口径

`ReportDesignerDialog`（ChromeWindow 外壳；无参构造给设计器与自动收面）逐行显示一个数据源的**全部列**：

| 控件 | 作用 |
|---|---|
| `CheckBox` | 勾选＝导出这一列（取消勾选＝**显式隐藏**） |
| `TextBox` | 直接改列名（留空或与原列名一字不差 ⇒ **不写覆盖**） |
| `↑` / `↓` | 在 `_rows` 里挪一格并重排面板（行序**就是**导出顺序） |
| `BtnReset` | 恢复默认＝用**空模板**重新铺开（原序、原名、全可见） |

两条界面口径：

1. **全都不勾 ⇒ 确定键不可点**：那种模板会让导出抛（`ApplyTemplate` 的"全隐藏"契约），
   界面上不该产生这种输入 —— 与时间范围对话框"自定义两端都空不可点"同一形状。
2. **一键未动地保存 ⇒ 交回空模板**（顺序没动、没改名、没隐藏）；`ReportTemplateSettings.Set`
   对空模板就是**删除** ⇒ 磁盘上不留空壳（阶段 182 已把这条判据钉住）。

### 7.2 🩸 本阶段最关键的一处：设计器不能拿"导出视图"当输入

`ApplyTemplate` 是**导出**视图 —— 被隐藏的列**已经不在里面**了。设计器若用它当输入，
用户一旦隐藏过一列就**再也勾不回来**（只能"恢复默认"，而那一刀把他的顺序与改名也一起清了）。
所以新增 `ReportTemplate.Spread(columns, template)`：**隐藏的列留在原位**并带 `Hidden`，
模板列到的键在前、没列到的按原序接在后面。

判据两条：Core `Spread_KeepsHiddenColumnsInPlace` ＋ App `Dialog_ShowsEveryColumn_InTemplateOrder`
（后者带前提自检"行数 = 列数"）。负控 nc6 把 `Spread` 改回"拿导出视图当输入"，两条一起红。

### 7.3 列清单只有一个来源

设计器只要**列**（历史数据的行可能上千）⇒ 三个数据源各加 `XxxReport.Columns(localize)`
（历史那条是 `Columns(variableIds, localize)`），`From(...)` 改为复用它。
判据 `ReportColumnUniverseTests` **5 条**逐源对拍 `Columns(...) ≡ From(...).Columns`
（顺序、列键、列名都比）—— 漂移的后果是"设计器里排好的顺序在导出时对不上"，而且**不报错**。

### 7.4 套用点：只有一处，而且只在「导出报表」这条路上

- 「导出报表」：建表 ⇒ **套模板** ⇒ 问范围/列 ⇒ 保存（模板改过的列名会带进列选择对话框，
  用户仍可临时取消几列）。
- 「报表包」：**刻意不套**（它是留档/交付：全列全时段）。这条分工由判据
  `TemplateIsAppliedOnlyOnTheReportPath` 钉住（每个面板里 `ReportExport.ApplyTemplate`
  **恰好出现 1 次**）—— 负控 nc5 往报表包那条路再加一次立刻红。
