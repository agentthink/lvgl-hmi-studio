# 阶段 119 —— 收口工具链收进 `scripts/`（并挂进门禁步 [1]）

> 一句话：把**收口**这一整套量具从 `.workbuddy/tmp/` 里的一次性脚本收进版本库
> （`gate-run.sh` / `gate-diff.py` / `gate-readings.py` / `face-residual.py`，各带 `--selftest`），
> 并把四个自检挂进门禁步 [1] ⇒ 「上一阶段那条 0 行差异」从此**事后可复算**。
> **产品代码 0 行改动**（只动 `scripts/`）。

## 119.1 起点：为什么这一刀必须是独立一批

登记表 §40.6 第 4 条原文：

> **`.workbuddy/tmp/` 脚本搬进 `scripts/` 要独立成一批** —— 一搬就动门禁步 [1] / [2] 的计数
> （脚本数、扫描面），**会让既有门禁读数当场作废**。本阶段**不动**，只登记。

读到这句话时它是**推测**。本阶段把它逐条验成事实（见 §119.2），并发现推测**少了一条**：
真正让读数作废的是步 [2] 的**文件计数**，而步 [1] 只数 `git ls-files '*.sh'` ⇒
往里加 `.py` **不动**它的计数。

## 119.2 量的那一遍：两条硬约束

| # | 约束 | 实测 |
|---|---|---|
| ① | 步 [1] 的「脚本数」只数 **`.sh`** | `ci-gate.sh` 用 `git ls-files '*.sh'` ⇒ 加 3 个 `.py` 不动这个数，**加 1 个 `.sh` 才 +1**（28 → 29） |
| ② | 步 [1c] 路径卫生扫 **`src/ tools/ scripts/ firmware/`**，且用 `git ls-files` | 计数 668 → **672**（+4）；且 `scripts/` 里**引号内**的 `/home/<别人>/…` 会被判红 ⇒ 收编时必须去掉硬编码家目录（原脚本全是 `ROOT = "/home/chen/Git/zhishu-hmi"`） |

⇒ 收编不是 `cp`，是**改写**：仓库根的定位一律改 `Path(__file__).resolve().parent.parent`
（与既有 `check-*.py` / `sync_localization.py` 同款）。

## 119.3 收编清单（4 件）

| 工具 | 干什么 | 自检 |
|---|---|---|
| `scripts/gate-run.sh` | 跑门禁并把**退出码写进日志正文**（固化「整条都在同一个 shell 里」那条唯一写法，防踩过 4 次的「半吊子 bash」） | 3 档 |
| `scripts/gate-diff.py` | 两跑日志对拍：**剥墙钟 → 多重集差 → 逐行位移 → 结构性归一** | 4 档 |
| `scripts/gate-readings.py` | 从一跑日志抽**收口表要用的每一个数**（含「关键项匹配不到就报警」） | 3 档 |
| `scripts/face-residual.py` | 五层动作面的**残余探针**（选题用：面 / 残余 / 覆盖） | 3 档 |

两类纪律被固化进代码，不再靠记：

- **`gate-readings.py`**：① 行数一律 `splitlines()`；② 关键项匹配不到 ⇒ **报警并非零退出**
  （`missing()` 就是阶段 118 那一脚的固化：程序集正则失效时打出的是「合计 0」，看着像「没数据」）。
- **`gate-diff.py`**：归一是「**拆结构 ＋ 丢空行**」，自检**档 4** 专门钉住「归一并不会把真内容差也吃掉」。

## 119.4 挂进门禁步 [1]（刻意**不**新开 banner）

**不加进门的判据等于没有判据** —— 这四个工具自己带 `--selftest`，而 `--selftest` 要是没人跑，
它就会跟工具一起腐烂；而它们正是「判断别的东西对不对」的**量具**。

⚠ 放在**步 [1] 之内**、不新开 `banner`：步数是日志的一条**口径**（`===== [N]` 的个数），
18 份历史日志都是 `7 步`；新开一步会让「读数对拍」当场失去可比性。
放进步 [1] 则**步数仍是 7**，只有行数增加（`849 → 853`，可由 `gate-readings.py` 逐项读出）。

## 119.5 🩸 两个「63」不是同一个 63

收编 `face-residual.py` 时顺手对了一下它和静态守卫的读数，两边都出现 **63**：

| 来源 | 口径 | 读数 |
|---|---|---|
| `face-residual.py`（本阶段收编） | **按钮类 · 名字级**：带 `x:Name` 的动作控件里，名字**从未出现在任何一层守卫源码**中的格 | 面 307 格 / 244 名字 / 43 视图；残余 **63 格 / 55 名字 / 20 视图**（覆盖 189/244 = 77.5%） |

**分子根本不同**，`63` 是巧合同数（一个是「名字没被提过的**按钮**格」，一个是「未分类的**选择**控件」）。
⚠ 这正是本仓吃过的那类错（门禁 `7 步` 与固件 host `9 步` 同列在日志尾部相邻三行，**连着三个阶段抄错**）
⇒ **引数字时把来源工具名一起写上**。探针的文件头注释里已把两个口径并排写明。

另：探针里 `PropertyPanelView` 是**残余 10 / 面 15**，而把 `PropertyPanelView` 记成 **31** 的是
**上面那张选择类普查表**、不是本探针 —— 阶段 118 那句「31 不是下一刀」引的是后者。

## 119.6 🩸 负控四支 —— **其中两支第一版是写假的**

| 支 | 注入 | 期望红 | 实测 |
|---|---|---|---|
| `N1` | `gate-readings.py` 摘掉**程序集**报警 | 档 3 | ✅ 档 3（`程序集为空却没报警`） |
| `N2` | `gate-diff.py` 去掉「拆回被挤的标记行」 | 档 3 / 档 4 | ✅ 档 3（`归一后应为 0，实为 3`）＋ 档 4（`应为 1，实为 4`） |
| `N3` | `gate-run.sh` 把 `GATE_EXIT` 写回终端而不写日志 | 档 1 / 档 2 | ✅ 档 1（`末行实为：ERR`）＋ 档 2（`实为：boom`）＋ 档 3 |
| `N4` | 往 `scripts/face-residual.py` 注入**引号内的** `/home/somebody/…` | 卫生检查红 | ✅ 见 §119.7 |

🩸 **N1 第一版没红，而「没红」的原因是我自己写假了**：注入写成

```python
    if not s["程序集"]:
        bad.append(...)
    elif len(s["程序集"]) != 10:
        bad.append(...)
    # ↓ 第一版注入
    if False:            # ← 只把 `if` 那一支短路
        bad.append(...)
    elif len(s["程序集"]) != 10:
        bad.append(...)
```

`if False: A elif cond: B` ⇒ **条件假时 `elif` 照样求值**，B 仍然执行 ⇒ 「程序集条数 0 ≠ 10」
照报，**判据行为根本没被摘掉**，负控成了**假绿**。
⇒ 教训：**负控必须摘「整块」**，而且要**验证判据真的不响了**（不是「跑完没报错」）。
这也正是本仓那条「做不出负控的判据不发布」的**执行细节**：负控自己也得被判一下。
改法是把两个分支一起换成 `pass`（还原后 md5 逐字节一致）。

`N2` / `N3` 一次就红，四支**还原后 md5 与基线逐字节一致**。

## 119.7 🩸 卫生面取决于「是否被 git 跟踪」⇒ 对**新文件**而言「落盘」＝「进索引」

`N4` 的分档实测（同一份注入，只改「跟不跟踪」这一个变量）：

| 时点 | 跟踪状态 | `check-path-hygiene.sh` | 计数 |
|---|---|---|---|
| ① 基线（未注入） | 未跟踪 | **绿** | 668 |
| ② 注入后 | **未跟踪** | **绿** ← **盲区** | 668（纹丝不动） |
| ③ 注入后 | **已 `git add`** | **红**，并点名 `207:_PROBE_PATH = "/home/somebody/secret"` | 669 |
| ④ 还原后 | 已跟踪 | 绿 | **669** |

⇒ **两支都成立**：卫生检查**确实**管到新文件，但**只在它被跟踪之后**。
⇒ 这条直接改写了批次模型的时序：那条「内容批门禁跑在**代码落盘之后、提交之前**」的纪律里，
「落盘」对**新文件**而言 ＝ **进索引**，不是「文件存在于磁盘上」。
本阶段据此把 `git add scripts/` 放到了门禁跑**之前**（不然这一步对 4 个新脚本是**空转**）。
门禁 [1c] 旁边已把这条写进注释。

## 119.10 诚实边界 / 未闭环

- 四个工具是**量具**，不是判据：它们**不参与**「产品对不对」的判定，只保证**读数可复算**。
- ⚠ `gate-readings.py` 的 `missing()` 里那条「程序集条数 ≠ 10」是**硬编码 8 ＋ 2 ＝ 10**
  （本仓门禁的调用次数）。门禁若增删一次 `dotnet test`，这条会**误报**；它是**有意的**告警
  （宁可报警也不要静默），但改门禁的人必须同时改这里。
- ⚠ 未跟踪文件对路径卫生是**盲区**（§119.7）。本阶段只**登记**这个事实，
  **没有**去改 `check-path-hygiene.sh` 的取数方式（改成 `find` 会丢掉「只查被跟踪文件」
  这个有用的性质，且会让 668 这个口径再一次漂移）。
- 登记表 §40.6 第 4 条**已闭环**（本阶段）；`#45` / `#66` / `#67` 与「面外 16 视图 / 63 选择控件」
