- 板子 `/etc` overlay 在 `/tmp`（tmpfs ramoverlay），**修改重启即丢** → 必须重编固件固化

## 2. 烧录流程（openixcli）

```bash
# 1) 板子进 FEL（Linux 下直接重启进 FEL，无需断电/按键）
cd /home/chen/Git/zhishu-hmi/firmware/t113/app
sudo python3 reboot_fel.py        # 发送: reboot bootloader

# 2) 确认设备
sudo /tmp/openixcli_extract/openixcli scan        # 必须显示 Found 1 device, mode Fel

# 3) 烧录（约 40s，期间勿断电/拔 USB）
sudo /tmp/openixcli_extract/openixcli flash /home/chen/Git/zhishu-hmi/firmware/Tina-SDK/out/t113-mq_r/tina_t113-mq_r_uart1.img
# 成功标志: [OKAY] All partitions flashed successfully + Device will reboot

# 4) 等 60s 后验证
sudo python3 verify_console.py
```

**烧录注意事项**：
- 板子在 U-Boot 提示符（`=>`）时**没有 `fel` 命令**（报 Unknown command）→ 用 `reset` 重启后进 FEL，或 Linux 下 `reboot bootloader`
- openixcli 输出 `Flash size: 0 MB` / `No UBIFS partitions found` 是正常提示，不影响
- 烧录覆盖 env 分区 → bootcmd 以固件 `env.cfg` 为准

## 3. 启动流程检查点（正常时序）

```
上电 → BOOT0 (DRAM init, 约 100ms)
  → U-Boot 2018.05 (sun8iw20, SPI NAND)
  → [01.0] sunxi flash init ok
  → [01.2] Loading Environment from SUNXI_FLASH... OK
  → bootcmd 执行: sleep 0; mtdparts default; ubi part sys; run setargs_nand_ubi; run boot_normal
  → [01.4] LCD open finish → ubi attach → sunxi_flash read boot → bootm
  → Linux 内核: VFS: Mounted root (squashfs) readonly
  → [16.5] procd init → Please press Enter to activate this console
  → 回车 → root@TinaLinux:/#
```

**正常启动的硬性检查点**：
1. 能到 `root@TinaLinux:/#`（不是 `=>`）
2. `ps | grep hmi` → hmi_runtime 在跑（procd respawn）
3. `/dev/input/event2` 是 **`c 13 66` 真实节点**（不是 `-> event1` symlink）
4. `ls -la /proc/$(pidof hmi_runtime)/fd/` → 有 `9 -> /dev/input/event2`
5. 屏幕显示 HMI 界面，触摸点击有响应

## 4. 触摸排查清单（分层定位）

> 核心思路：**从硬件到应用逐层验证**，每层都有独立的判定方法。

### 4.1 硬件层（GT911 IC 是否在线、是否发中断）
```bash
sudo python3 diag_touch.py        # 一次收集中断表/驱动日志/输入设备/GPIO
# 或手动:
cat /proc/interrupts | grep gt9xxnew_ts    # 有无触摸中断项
cat /proc/interrupts | grep PA3_EINT        # 触摸时计数应增长 (GT911 INT 引脚)
```
**判读**：
- `PA3_EINT` 计数触摸时**增长** → 硬件 + 中断链路 OK，问题在驱动/上层
- 计数**不变** → GT911 没发 INT（硬件/复位/配置问题，如排线、供电）

### 4.2 驱动层（gt9xxnew_ts 是否 probe 成功）
```bash
dmesg | grep -iE 'gt9|goodix|ctp'      # 应有: input: gt9xxnew_ts as .../input/inputN
cat /proc/bus/input/devices            # 应有 Name="gt9xxnew_ts", Handlers=eventN
cat /proc/modules | grep gt9           # 模块已加载
```
**常见警告**（`ctp_power is fail, -22` 等，可忽略，不影响触摸）：
```
get ctp_power is fail, -22 / sunxi_ctp_startup: ctp_power_io is invalid / supply ctp not found
```

### 4.3 设备节点层（eventN 是否正确）
```bash
ls -la /dev/input/                     # event2 必须是 crw 13,66，不是 symlink!
cat /sys/class/input/event2/dev        # 应输出 13:66
```
**典型错误**：`event2 -> /dev/input/event1`（symlink）→ GT911 真实节点被覆盖 → 触摸失效
- 原因：S97hmiruntime 旧版硬编码 `ln -sf event1 event2`（GT911 曾为 event1，升级后变 event2）
- 修复版已改为动态检测（见 5.1）

### 4.4 事件流层（触摸事件是否进入节点）
```bash
# 板上: dd 读 event2, 触摸时文件应 >0
dd if=/dev/input/event2 of=/tmp/t.dat bs=24 count=5 & sleep 6; wc -c /tmp/t.dat
```
- `>0` → 驱动上报正常
- `=0` → 节点不对（见 4.3）或驱动未上报（见 4.2）

### 4.5 应用层（hmi_runtime 是否消费）
```bash
pidof hmi_runtime                     # 必须存在
ls -la /proc/$(pidof hmi_runtime)/fd/ | grep event   # 必须打开 /dev/input/event2
ls /etc/init.d/S97hmiruntime          # 脚本必须存在
ls /etc/rc.d/S97hmiruntime            # symlink 必须存在（否则不自动启动）
```

## 5. 已修复问题速查（本次踩坑）

### 5.1 触摸失效：S97hmiruntime 错误 symlink
- **症状**：GT911 硬件正常（中断增长），但 UI 无触摸
- **根因**：`package/hmi-runtime/files/S97hmiruntime` 旧版硬编码 `TOUCH_SRC=/dev/input/event1`，执行 `ln -sf event1 event2` 覆盖 GT911 真实节点（固件升级后 GT911 变 event2）
- **修复**：改为动态检测 `gt9xxnew_ts` 真实节点，仅当真实节点≠event2 才建 symlink

### 5.2 rootfs 缺 hmi-runtime
- **根因**：`make defconfig` 把 `CONFIG_PACKAGE_hmi-runtime` 从 y 重置为 m
- **修复**：改回 y；**且注意** rootfs.img 打包源是 `compile_dir/target/rootfs`（非 staging_dir），改 .config 后需确保该目录含包文件，必要时手动补齐 + 重跑 mksquashfs：
```bash
# 手动重打包 rootfs.img
rm -f out/t113-mq_r/rootfs.img
out/host/bin/mksquashfs4 out/t113-mq_r/compile_dir/target/rootfs \
  out/t113-mq_r/compile_dir/target/linux-t113-mq_r/root.squashfs \
  -noappend -root-owned -comp gzip -b 256k -p '/dev d 755 0 0' -p '/dev/console c 600 0 0 5 1' -processors 10
dd if=out/t113-mq_r/compile_dir/target/linux-t113-mq_r/root.squashfs of=out/t113-mq_r/rootfs.img bs=128k conv=sync
```

### 5.3 开机停在 U-Boot 不自动启动
- **根因 1**：新 U-Boot 启动时 UBI 未 attach，`sunxi_flash read boot` 报 `no UBI device selected`
- **根因 2**：`boot_dsp0` 引用不存在分区，失败中断 run → `boot_normal` 不执行
- **修复**（`device/config/chips/t113/configs/mq_r/env.cfg`）：
```
bootcmd=sleep ${bootdelay}; mtdparts default; ubi part sys; run setargs_nand_ubi; run boot_normal
```
- 已烧录板子可在 U-Boot 手动救活：`setenv bootcmd '...'; saveenv; boot`（U-Boot 直接写 flash，无需 fw_setenv）

### 5.4 触摸时跳转 lvgl demo 页面
- **根因**：`package/allwinner/swupdate/swupdate_autorun.init` 第 23 行 `lv_examples 0 &` 与 hmi_runtime 抢占 /dev/fb0 和 event2
- **修复**：注释该行（HMI 由 hmi_runtime 独占显示与触摸）

## 7. 其他注意事项

- **串口 shell 卡在 `>`（PS2）**：之前残留未闭合命令/tty 状态 → 运行 `recover_serial.py`；顽固时断电重启
- **串口命令输出为空但 shell 正常**：检查脚本是否一次性发送大命令（应逐字符低速发送）
- **编译/打包**：改 SDK 源文件（如 S97hmiruntime、env.cfg、swupdate_autorun.init）后：`source build/envsetup.sh && lunch t113_mq_r-tina && make`（**勿跑 defconfig**）`&& pack`；改 compile_dir 后手动 mksquashfs
- **hmi_runtime 依赖**：libpng12.so.0（Makefile 已从 STAGING_DIR 复制 workaround Tina 包路径 bug）、libuapi、libfreetype
